## Изменения v0.2 — художественная карта и просмотр без управления

- Карта представлена готовыми изображениями из `assets/*.webp`, а не SVG-линиями и нарисованными кодом клетками. Текущая позиция и история представлены отдельно текстом и лентой прогресса.
- Убраны редакторы игр/аукционов/оформления, переименование, удаление сезона, импорт/экспорт, отмена действий и редактирование профиля с основного экрана. Существующие сохранения не удаляются.
- Названия и цели исходных испытаний определяются в `game.mjs` (константы `SAMPLE_GAMES`, `SAMPLE_AUCTIONS`): изменить их можно через GitHub с новой версией приложения. Существующие сезоны продолжают использовать сохранённые в Firestore данные.
- Новая `view.html` — общедоступная афиша сезона без авторизации, голосования или управляющих кнопок. Публикует её только владелец из кабинета. URL копируется кнопкой.
- Для работы публикации **необходимо вручную обновить вкладку Firestore → Rules**, заменив содержимое на файл `firestore.rules` из этой ветки, затем нажать Publish. Коммит в GitHub НЕ развёртывает правила автоматически.
- Данные публичной страницы сохраняются отдельно в `publicSeasons`, куда попадает только ограниченный набор полей (без почты, пароля и истории ходов).
- Пока зрители не могут голосовать в аукционах — только следить за результатом. Зрительская интерактивность проектируется следующим этапом.

**Важно:** сайт пока использует существующие иллюстрации карт из репозитория; для по-настоящему новой детализированной карты с пронумерованными клетками требуется отдельный графический арт и разметка точек фишки. В этой версии клеточная лента намеренно находится отдельно от рисунка. Не объединяйте изменения с основной веткой до проверки публичных правил и публикации.

### Быстрая проверка перед объединением
1. Проверить авторизацию и открытие существующего сезона.
2. Убедиться, что игровой экран не содержит редактора и карта отображается целой картинкой.
3. Применить Firestore Rules через консоль Firebase.
4. Владелец нажимает «Опубликовать сезон» и копирует ссылку.
5. Открыть ссылку в приватном окне: видно карту и текущую позицию, но нет кнопок.
6. Из кабинета сделать бросок; публичная страница должна обновиться сама.
7. Закрыть просмотр и проверить, что в приватном окне больше не доступно состояние сезона.

# FARS — Гастроли проклятых · прототип v0.1

Готовый статический сайт с личными кабинетами стримеров, картой игрового цирка, аукционами, сохранением сезонов в Firebase Firestore и демонстрационным локальным режимом. OBS не нужен. Визуальная основа — выбранный пользователем референс цирка Fars, разрезанный на три тематических изображения.

## 1. Что уже есть

- Вход и регистрация по почте и паролю через Firebase Authentication.
- Индивидуальная история и сезоны каждого стримера в Cloud Firestore. Данные другого стримера недоступны благодаря `firestore.rules`.
- Несколько сезонов на один аккаунт: выбор, переименование, создание, удаление.
- Три темы: «Манеж», «Ковровая дорожка», «Закулисье».
- 19 позиций: старт (0) + 18 клеток (финиш на 18).
- Обязательные игры на 3, 8, 12, 17: случайным кубиком перепрыгнуть нельзя.
- Аукционы на 6, 10, 15: три заранее заданные игры, результат вручную выбирает стример. Автодонатов и автоматических зрительских ставок пока нет.
- Бонусные жетоны, случайные события, клетки выбора, кубик D3 (1–3), контрольные точки, история ходов, отмена одного действия.
- Редактирование игр и аукционных вариантов без кода.
- Экспорт сезона в JSON и импорт как нового отдельного сезона.
- Адаптация под мобильный экран (полноценная работа удобнее на компьютере).
- Демо-режим без аккаунта. **Прогресс демо хранится только в localStorage одного браузера, никакого облака в демо нет.**

## 2. Самый лёгкий способ попробовать

Опубликуйте содержимое папки через GitHub Pages по разделу 4. Сначала можно не подключать Firebase — нажмите «Попробовать демо без регистрации». Не открывайте `index.html` двойным кликом из проводника: ES-модули работают через HTTP/HTTPS. GitHub Pages предоставляет HTTPS.

Локальный запуск, если установлен Python: откройте командную строку в папке проекта и выполните `python -m http.server 8000`. Затем откройте `http://localhost:8000/`.

## 3. Создаём Firebase (можно на бесплатном Spark)

1. Перейдите на https://console.firebase.google.com/ и создайте проект `fars-circus` (имя можно другое). Аналитика необязательна.
2. Откройте **Project settings → General → Your apps → Add app → Web** (`</>`). Зарегистрируйте веб-приложение.
3. На экране отобразится объект `firebaseConfig`. Откройте `firebase-config.js` в Блокноте и подставьте **только четыре** параметра `apiKey`, `authDomain`, `projectId`, `appId`. Сохраните файл. Не нужен `serviceAccount`, приватный ключ или пароль.
4. В Firebase откройте **Build → Authentication → Sign-in method → Email/Password → Enable**.
5. В **Authentication → Settings → Authorized domains** добавьте домен `ВАШ_ЛОГИН.github.io` (только домен, без `https://` и пути `/название-репозитория/`). Для локального теста добавьте `localhost`, если его нет. Названия меню могут немного меняться.
6. В **Build → Firestore Database → Create database** создайте базу данных Cloud Firestore в подходящем регионе, в стандартном/production mode. При выборе региона учитывайте доступность и задержки для аудитории. 
7. Откройте вкладку **Rules**, полностью замените её содержимое на правила из `firestore.rules` и нажмите **Publish**. **Без публикации правил не выпускайте сайт с реальной регистрацией.**
8. Проверьте в Auth регистрацию и авторизацию двух тестовых аккаунтов. У второго не должно быть сезонов первого.

Конфигурация Firebase для веб-приложения публична по дизайну и может находиться в GitHub. Безопасность обеспечивают **Security Rules и Authentication**, а не скрытый `apiKey`. Никакие пароли и секретные ключи в репозиторий не загружайте.

### Ограничение безопасности первой версии

Регистрация сейчас открытая: любой посетитель сайта сможет создать собственный аккаунт. Он не увидит чужие сезоны, но может расходовать квоты Firebase своими сезонами. Перед крупным публичным релизом желательно добавить ограничение регистраций (например, приглашения / админское одобрение) и защиту от злоупотреблений. Для небольшого закрытого теста можно делиться ссылкой только с участниками, но это не техническая защита от регистраций.

## 4. Публикуем сайт на GitHub Pages без командной строки

1. Зарегистрируйтесь/войдите на https://github.com/ .
2. Создайте **New repository** с названием `fars-circus-game`, видимость **Public**, по желанию добавьте README.
3. В репозитории выберите **Add file → Upload files**. Перетащите содержимое распакованной папки проекта: `index.html`, `app.mjs`, `game.mjs`, `storage.mjs`, `style.css`, `firebase-config.js`, `firestore.rules`, файлы README и каталог `assets` со всеми файлами. Важно сохранить папку `assets`. При необходимости загрузите её отдельно через веб-интерфейс GitHub, сохраняя путь.
4. Нажмите **Commit changes**.
5. Откройте **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main, /(root) → Save**.
6. Сайт станет доступен по адресу вида `https://ВАШ_ЛОГИН.github.io/fars-circus-game/`. GitHub может опубликовать его не мгновенно.
7. Если Firebase вы настроили после публикации, обновите файл `firebase-config.js` в GitHub через кнопку редактирования (значок карандаша) и сделайте commit. Не забудьте домен из шага 3.

В архиве есть `.nojekyll`. Это помогает GitHub Pages публиковать приложение как обычные статические файлы. Сервер, Node.js, платный хостинг и базы данных на GitHub не требуются.

## 5. Первый тест

1. Откройте сайт. Если Firebase ещё не настроен, нажмите демо. Иначе создайте тестовый аккаунт.
2. Проверьте, что отображается «Первые гастроли», позиция 00 и 19 клеток.
3. Поменяйте тему на «Ковровую дорожку», затем обратно на «Манеж».
4. На карте нажмите клетку 3 → справа отредактируйте игру → сохраните.
5. Бросайте кубик до клетки 3. Игра должна остановиться на клетке 3, даже если бросок мог бы перепрыгнуть её.
6. Нажмите «Игра пройдена». Проверьте историю и счетчик.
7. Дойдите до клетки 6. Выберите победителя аукциона и завершите игру.
8. Скачайте резервную копию и импортируйте как новый сезон.
9. Перезагрузите вкладку: облачный прогресс должен сохраниться после входа в тот же аккаунт. В демо — только на том же браузере.
10. Создайте второй тестовый аккаунт и убедитесь, что данные первого не появляются.

## 6. Если что-то пошло не так

- **Пустая страница:** открывайте через GitHub Pages или локальный HTTP-сервер; не из `file://`. Убедитесь, что структура папок сохранена.
- **Отказ доступа / permission-denied:** опубликуйте `firestore.rules` в Firebase и убедитесь, что вы вошли в аккаунт.
- **Не работает вход:** проверьте включение способа Email/Password, корректность 4 полей `firebase-config.js` и Authorized domains.
- **Видно только демо:** не заполнены параметры конфигурации Firebase или не опубликовалось обновление GitHub Pages.
- **Не сохраняются сезоны:** проверьте включение Firestore Database и вкладку браузера DevTools → Console (F12).
- **Удалили сезон:** если ранее скачивали JSON, импортируйте его. Отмена одного действия не восстанавливает удалённые сезоны.
- **Откат сайта:** GitHub → вкладка Commits/History → вернитесь к предыдущему коммиту. **Откат кода не откатывает данные Firestore.**

## 7. Что пока НЕ реализовано

- Публичная страница отдельного сезона по ссылке для зрителей.
- Онлайн-ставки и таймер с синхронизацией для зрителей (в v0.1 результат аукциона вводит ведущая).
- Интеграция со Steam и автоматическая проверка прохождения.
- Синхронное редактирование одного сезона с нескольких устройств: последнее сохранение может перезаписать другое.
- Приглашения/модерация регистраций, роли помощников, глобальный список стримеров и административная панель.
- Анимации перемещения фишки и кастомная графика игровых карточек (в v0.1 шаг мгновенный).

Все эти функции можно добавить без OBS. Для следующей версии полезнее всего сделать публичную ссылку с чтением карты, realtime-режим и отдельный зрительский аукцион.

## 8. Технические сведения

- Статика: HTML, CSS, нативные JavaScript ES modules. Сборка не требуется.
- Облако: Firebase JavaScript SDK (CDN v13.1.0, ссылка из официальной документации), Authentication (Email/Password), Cloud Firestore.
- Firestore: `/streamers/{uid}` → профиль, `/streamers/{uid}/seasons/{seasonId}` → состояние сезона одним документом.
- Нет серверного кода, сервисных аккаунтов или API-ключей сторонних платежных систем.
- Проверка логики: `node --test tests/game.test.mjs` (нужен Node.js версии 20+). Браузерные проверки демо выполнены отдельно; реальный Firebase не протестирован без проекта.
